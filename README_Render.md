# Render Deployment

The production webserver is named kmmdsr and is available at https://kmmdsr.onrender.com. It deploys from DPMKMM/DSR, branch main, using the repository Dockerfile.

## Deployment behavior

- The service runs in Singapore on Render Free.
- The repository Blueprint is render.yaml.
- The service is configured to deploy commits from main.
- /health is the liveness endpoint.
- The home page is the direct file-upload interface; it does not require an API token from users.
- The webserver uses local SQLite job tracking and stores generated PDFs under DATA_DIR.

The existing service keeps its current session-signing secret for compatibility. New Blueprint-created services use WEB_SESSION_SECRET, generated by Render. Do not put a session secret in source control or share it in public messages.

## Important storage limit

Render Free does not provide persistent local disks. Files under /tmp/khammam-attendance-data can be cleared when the service restarts, redeploys, or spins down. Download each report and keep your own copy. If report history and PDFs must survive service restarts, choose a persistent storage option and review any associated charges before enabling it.

## Deploy updates

Push code changes to main; Render builds and deploys the linked branch. Verify the new deploy becomes Live, then check:

- https://kmmdsr.onrender.com/health
- https://kmmdsr.onrender.com/

Keep the legacy service available until the new service has been verified. Do not store uploads, PDFs, SQLite files, or secrets in Git.

## Local Docker check

~~~powershell
docker build -t khammam-ps-attendance .
docker run --rm -p 8080:8080 -e WEB_SESSION_SECRET=replace-with-a-random-secret-of-at-least-32-characters -e DATA_DIR=/tmp/khammam-attendance-data khammam-ps-attendance
~~~

Open http://localhost:8080/ and http://localhost:8080/health.
